Kernel hardening (sysctl)

16 kernel parameters hardened covering memory protection, BPF JIT hardening, ptrace scope, network redirect blocking, and martian packet logging. Note: kernel.modules_disabled=1 intentionally skipped — breaks Kali drivers.

sys
Apply sysctl values
36/37 OK ▼ 
cat >> /etc/sysctl.conf << 'EOF'
# Kernel hardening
kernel.dmesg_restrict = 1
kernel.kptr_restrict = 2
kernel.sysrq = 0
kernel.unprivileged_bpf_disabled = 1
kernel.yama.ptrace_scope = 1
dev.tty.ldisc_autoload = 0
fs.protected_fifos = 2

# Network hardening
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.log_martians = 1
net.ipv4.conf.default.log_martians = 1
net.ipv4.conf.all.rp_filter = 1
net.ipv6.conf.all.accept_redirects = 0
net.ipv6.conf.default.accept_redirects = 0
net.core.bpf_jit_harden = 2
EOF

sysctl -p
⚠
sysctl values revert if VPN reconnects. Run sysctl -p again to re-apply.

Authentication hardening

Password policy & aging
done ▼ 
# PAM password strength (12 char min, complexity required)
cat > /etc/security/pwquality.conf << 'EOF'
minlen = 12
dcredit = -1
ucredit = -1
ocredit = -1
lcredit = -1
maxrepeat = 3
EOF

# Password aging
sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS\t90/' /etc/login.defs
sed -i 's/^PASS_MIN_DAYS.*/PASS_MIN_DAYS\t1/'  /etc/login.defs
sed -i 's/^PASS_WARN_AGE.*/PASS_WARN_AGE\t7/'  /etc/login.defs

# SHA512 hashing rounds & umask
echo "SHA_CRYPT_MIN_ROUNDS 65536"  >> /etc/login.defs
echo "SHA_CRYPT_MAX_ROUNDS 655360" >> /etc/login.defs

echo "umask 027" >> /etc/profile

echo "readonly TMOUT"  >> /etc/profile
echo "export TMOUT"    >> /etc/profile

# Apply expiry to accounts

-w /etc/gshadow -p wa -k identity

# Privilege escalation
-w /var/log/auth.log -p wa -k auth

# SSH & network
-w /etc/ssh/sshd_config -p wa -k ssh

-w /etc/network/        -p wa -k network

# Cron

# Kernel modules

Initialize AIDE with explicit SHA512 checksums. The database build takes 2–13 minutes depending on filesystem size.

# Override default checksum to SHA512 explicitly

aide -c /etc/aide/aide.conf --init

# Verify database exists

Compiler hardening

Lynis checks as, cc, gcc, and clang — following symlinks to real binaries. The GNU assembler (as) was the final culprit along with mingw cross-compilers.

gcc
Restrict all compilers to root only
done ▼ 
# Restrict cpp (follows symlink chain to real binary)
chmod o-rx /usr/bin/cpp
chmod o-rx /usr/bin/cpp-15
chmod o-rx /usr/bin/x86_64-linux-gnu-cpp-15

# Restrict as/assembler (Lynis treats as compiler)
chmod o-rx /usr/bin/as
chmod o-rx /usr/bin/x86_64-linux-gnu-as

# Restrict mingw cross-compilers
find /usr/bin -name "*mingw*cpp*" \
              -o -name "*mingw*gcc*" | \
  xargs chmod o-rx 2>/dev/null

find /etc/alternatives -name "*mingw*cpp*" \
                        -o -name "*mingw*gcc*" | \
  xargs chmod o-rx 2>/dev/null

# Verify — should show r-x--- (750) for all
ls -la /usr/bin/as /usr/bin/cpp /usr/bin/x86_64-linux-gnu-as
✓
Root can still compile normally. This only restricts non-root users from running compilers — safe for a pentest machine where you operate as root.

Intentionally skipped

⚠
88/100 is the maximum achievable score on a functional Kali pentest laptop without a full reinstall. The remaining 12 points require changes that would break the system or require repartitioning.
  • ✗
    kernel.modules_disabled=1 KRNL-6000
    Setting to 1 after boot prevents loading any kernel modules. Breaks network adapters, USB devices, Kali drivers, and most offensive tools. Incompatible with pentesting.
  • ✗
    Separate /home partition FILE-6310
    Requires full disk repartitioning and OS reinstall. Not feasible on a working machine mid-engagement.
  • ✗
    Separate /var partition FILE-6310
    Same — requires reinstall. /var contains logs, databases, and package cache; moving it live risks corruption.
  • —
    External log host LOGG-2154
    No remote syslog server available. Would require infrastructure setup outside scope of this engagement.
  • —
    Automation tooling TOOL-5002
    Chef/Puppet/Ansible not relevant for a standalone pentest laptop.
